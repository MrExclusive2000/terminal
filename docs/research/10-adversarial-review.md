# Adversarial review

> Four independent red-team passes over the draft plan: completeness, feasibility and cost,
> security and legal, and UX. 121 gaps, 42 corrections. Findings the reviewers could not
> corroborate against a primary source are labelled as such — treat those as leads, not facts.


## Review pass 1

**Verdict.** The specification is excellent research and a fantasy schedule. The effort model is internally derivable — S=1 day, M=2 days, L=1 week, XL=2.5 weeks — and at that rate a bitemporal XBRL engine, a bidirectional NL↔AST↔DSL alert compiler, an eight-jurisdiction insider desk, and a hand-written UIA provider layer are each "2.5 weeks." The honest number for the scope as written is 380–520 engineer-weeks, not 138; at a realistic solo throughput of ~0.65 productive ew per calendar week that is 11–15 years, and even the P0-only slice is 5–6 years. The arithmetic is also wrong in a checkable way: the module tables enumerate 274 features, not the 240 the rollup prices, so 34 features carry zero effort. The data-cost table is broadly right on unit prices (I confirmed Nasdaq TotalView non-pro $15.00, Massive Advanced $199, Databento Standard $199, Norgate Platinum ~$52.50, SciChart $899) but omits the two largest AI line items — a nightly 200-question Opus-xhigh eval gate is $1,350–2,700/month against a total AI budget of $217 — and the knowledge-pack pipeline is architecturally dead because Claude Code Routines caps at 5–25 runs/day, which the plan lists as "unresolved" when it is published. The single biggest missed saving is that SEC DERA publishes flattened quarterly Form 3/4/5 datasets back to 2006Q1 (82 ZIPs, ~1.1 GB, with footnotes and footnote-join keys already structured); the plan instead designs a ~5M-document XML crawl at 3 req/s, which is ~19 days of continuous polling for data that downloads in minutes.

### Corrections

- Feature count is wrong. The module tables enumerate 274 features (14+15+14+17+32+14+12+13+12+8+8+12+23+10+8+14+16+8+7+17), not the 240 the Priority Rollup prices. The effort distribution (S71+M108+L48+XL13=240) therefore omits 34 features entirely, and every percentage in the rollup (P0 45%, etc.) is wrong. Recount before any estimate is defensible.
- 'Roughly half the raw Form 4 universe is mechanical compensation activity' understates it. Measured directly from SEC DERA 2025Q1 NONDERIV_TRANS (103,029 rows): A=24.5%, F=26.6%, M=15.5% — 66.6% non-discretionary. Code P is only 5.5% (5,681 rows/quarter, ~22,700/year market-wide). Use 67%, not 'roughly half' — it strengthens the argument and is verifiable.
- Insider row sizing is ~3x low. Plan says 3.6M insider_transaction rows for 2006–. Actual: 142,000 transaction rows per quarter (103,030 non-deriv + 38,925 deriv, 2025Q1) x 82 quarters ≈ 11.6M rows, plus ~13M footnote rows (158,490/quarter). Storage is still fine, but the number was clearly not computed.
- 'Global Insider Desk ... All free at origin' is false for at least three legs. UK regulatory news is distributed via RNS, a commercial LSE feed; the FCA National Storage Mechanism is free but is an unstructured document store. Japan EDINET requires a registered API key and returns Japanese-language XBRL. Canada SEDI has no bulk or documented API. India SEBI PIT 7(2) disclosures land as per-exchange HTML/PDF. Correct the Data source column to 'free at origin (US, EU NCA registers); commercial or scrape-only (UK RNS, HKEX, SEDI, India)'.
- The Claude Code Routines daily run cap is published and resolves against the design: Pro 5 routines/day, Max 15/day, Team/Enterprise 25/day (research preview, launched 2026-04-14). The plan lists this as UNRESOLVED and assumes ~800 packs can be authored nightly. At 15 runs/day the stated 'one Routine per pack class' architecture is impossible; the pipeline must move to a plain GitHub Action calling the Batch API, which is a per-token cost, not a flat subscription. Also correct the claim that the fallback loses the Batch discount — the Messages Batch API is available to API callers and is where the discount lives.
- Vector-store sizing contradicts the plan's own storage table. Diagram E sizes extracted filing text at ~14 GB; at 600–900 tokens/chunk that is ~4.5–5M chunks, not the ~200k the retrieval stack (13.3) and the atomic rebuild (13.22) assume. sqlite-vec brute force over 4.7M int8/512-dim vectors is a ~2.4 GB scan per query — seconds, not the claimed <100 ms. Either cap the embedded corpus (watchlist names only, ~200k chunks, which is defensible) and say so, or accept an ANN index and its corruption failure mode.
- Databento Standard $199/mo is per dataset family — US Equities, OPRA, CME, ICE are separately priced $199 plans. The professional-column cost table treats it as one all-in line. If depth, options and futures are all wanted the professional spine is $400–800/mo before exchange pass-through, not $199.
- Two feature-table rows contradict the architecture section of the same document. Module 1.1 and 16.1 specify 'Syncfusion DockingManager (Community $0)', which the architecture explicitly rejects in favour of Dirkster.AvalonDock with a stated correlated-licence-failure rationale. Module 12.10 specifies 'Quartz.NET + SQLite AdoJobStore', which the architecture explicitly rejects in favour of RAMJobStore + a watermark table. Pick one per item; a builder cannot act on both.
- 'Form 144 ... Essentially nobody surfaces it' is overstated. Washington Service, VerityData/InsiderScore, Bloomberg and several free aggregators surface Form 144. The defensible claim is narrower and still strong: nobody at a solo price point runs a stateful 144→Form 4 matcher that flags the abandoned-sale case.
- SciChart WPF Professional $899 includes 1 year of support and updates; the perpetual licence continues but later builds require renewal. The plan's 'Yr-2+ $0 (opt. major upgrade ~$449)' and the $629 no-support figure are unconfirmed and should be quoted from store.scichart.com before the budget is fixed.
- The prompt-injection defence rests on Opus 5's mid-conversation role:"system" channel being non-spoofable. That is model-specific behaviour on a model that will be deprecated inside the build window. Do not make it a load-bearing architectural invariant without a fallback that survives a model swap.

## Review pass 2

**Verdict.** This is a strong plan for a US-equities, event-driven single-stock day desk with a world-class insider layer bolted on — and it is not the plan the brief describes. "Equities + FX" is really "US common stock + FX macro context": no ETF/fund module, no sector-specific fundamental templates (a bank, REIT, insurer, E&P or miner is unanalysable with Module 4 as written), no ADR/FPI handling, no non-US fundamentals path (companyfacts is us-gaap only; IFRS/ESEF/EDINET/SEDAR+ are absent while "global equities" is claimed), no futures, no credit view of the issuers being analysed. Lifecycle coverage is thin at both ends: nothing for the Sunday FX open, nothing for the closing auction, nothing for returning after two weeks away, and nothing for a stock that goes halt to suspension to Form 25 to Form 15 to Chapter 11 — at which point filings stop permanently and the terminal would render a dead company as a coverage gap. The single most-used screen in any real book, a live P&L blotter, is not among the six shipped workspaces; neither is Earnings Day. Structurally the plan is calibrated for an event-reactive trader and forgets nearly everything the ex-Rothschild/Buffett-school analyst it invokes actually does: 20-year owner-earnings series (companyfacts starts ~2010 with no substitute named), capital-allocation scorecards, an editable driver model, a per-company KPI and guidance ledger, an idea pipeline with review cadence, and a written memo output. Finally there are contradictions that block construction: the two sections disagree on docking manager, grid, scheduler and FX pricing; the alert UI offers an email channel the architecture cannot deliver; and headless overnight runs need vault credentials while the vault is locked behind Windows Hello.

### Corrections

- Nasdaq TotalView professional fee: the plan states $84.00/month for 2026 and $86.00 for 2027. Nasdaq's published 2025-2027 US equities price list gives $80.50 per professional subscriber for 2026 (the $15.00 non-professional figure is correct). Re-read Nasdaq_US_Equities_Price_List_2025_2026_2027.pdf and correct every derived professional-column total and the '5.6x' multiple.
- Ken French Data Library is NOT US-only. Feature 15.5 says factor attribution is 'reconciled monthly to the academic factors (US-only, ~1 month lag)'. The library publishes Fama/French factors for North America, Europe, Japan, Asia Pacific ex-Japan, developed and emerging markets, all in USD. This removes a stated limitation that does not exist and materially expands factor attribution for a non-US book.
- 'The Opus 4.7+ tokenizer emits ~30% more tokens for identical text' is asserted as fact and used to invalidate the whole AI cost model. It is not sourced to any primary Anthropic document in the plan. Replace with an instruction to baseline empirically with count_tokens on representative payloads before committing the AI budget.
- 'Citations and structured outputs are mutually exclusive (400 error)' drives an architectural decision (two calls for cited JSON, with latency and cost consequences). Re-verify against the current API before locking it in; if it has been fixed, a class of two-call designs collapses to one.
- The plan repeatedly frames the advice perimeter as switching on when 'a second USER of the software appears'. The actual trigger for the Advisers Act, FCA Art.53 and MiFID II is advising or managing another PERSON'S money, or communicating a recommendation to another person — which can happen with zero additional installs (a family member's account, an informal partnership, a fund seeded later). Reframe as 'a second person's money or a second person's eyes on the output', not 'a second install'.
- Non-professional market-data status is not solely an LLC question. Employment by a financial firm in a covered role, registration with any regulator or exchange, and use of the data for any business purpose each independently make the subscriber Professional regardless of whose money is traded. The Entitlement Console checklist has these boxes but the surrounding narrative repeatedly reduces the fork to 'if he incorporates', which will mislead the reader who is already employed in the industry.
- Several load-bearing claims are unsourced to any primary document and should each be re-verified at a named URL or downgraded to 'reported, unconfirmed': the IMF COFER unallocated-series elimination from 2025Q3 with revisions to 2000Q1; Cboe EVZ discontinuation; a House trading ban passing 232-198 in July 2026; 18.1m API keys exposed from malware in the 2026 reporting period; the Sharp7Extend payload timed for 2027-28; and the assertion that SR-FINRA-2026-012's 2026-08-14 decision date passed with no order.
- 'Item 402(v) Pay-versus-Performance is the ONLY Inline-XBRL-tagged comp slice' is overstated — cover-page dei facts and the Rule 10D-1 clawback checkboxes are also tagged. The substantive and correct point is that the Summary Compensation Table and the CD&A metric definitions are untagged and require extraction; state it that way.
- Massive Currencies is priced at $79/month in the feature and verified-pricing tables but $49/month in Tier B of the running-cost table, while the architecture section separately admits the whole Currencies tier structure is inferred from a secondary source. One number, one source, or an explicit range carried consistently.
- Syncfusion Community eligibility as stated (<$1M gross revenue, 5 or fewer developers, 10 or fewer employees, never more than $3M outside capital) matches Syncfusion's published terms and is correct — but the plan lists it as an open question in one section and as settled in another. Carry the architecture section's stronger argument instead: the licence keys on the licensee entity's revenue, the same variable that flips market-data status, which is a correlated failure regardless of current eligibility.

## Review pass 3

**Verdict.** The security section is unusually literate about mechanisms and unusually naive about how they compose. It picks the right two adversaries and then builds controls that do not stop either: the VBS/TPM key ladder stops key *exfiltration* but not key *use* by malware running as the same user, and the plan's own headless `--refresh` scheduled task and Excel named-pipe bridge quietly hand that malware everything anyway. The supply-chain story collapses to "GitHub Actions secrets in a repository an autonomous Claude agent has write access to" — the agent can commit a workflow file, and a tag-triggered workflow runs from the tagged ref with the signing secrets, so "the agent commits, only CI signs" is false as designed. The single most exploitable chain in the whole document is unremarked: injected filing text → model-authored screener DSL → DuckDB, which by default can `INSTALL`/`LOAD` extensions, read `http://`, and `COPY TO` a UNC path. On legal, the plan verifies US exchange price lists carefully and then gets the genuinely applicable regimes wrong: it never fixes the user's jurisdiction, treats UK/EU GDPR as a telemetry question when the product is a profiling database of named third-party directors, ignores the sui generis database right on its own "Local Insider Archive", ignores the Computer Misuse Act on the Senate eFD scrape, ignores the Ethics in Government Act's commercial-purpose prohibition on congressional disclosure reports, assumes a ZDR org it cannot obtain, and — fatally for a vendor audit — routes licensed vendor data into Anthropic and Voyage prompts while claiming a "Derived-Works Firewall" that only gates exports and clipboard.

### Corrections

- ZDR IS NOT AVAILABLE AS SPECIFIED. Feature 13.23 'Two-Identity Split' puts the interactive path on 'a ZDR org' and calls this 'a genuine security property'. Anthropic zero-data-retention is available only to qualified Claude for Enterprise accounts, is not enableable from admin settings, and requires the account team to review and enable it per organisation. A solo user on the Build tier ($1,000 cap) does not get it. The plan's headline confidentiality control for 'the watchlist is the alpha' does not exist at this price point. Either the interactive path runs with standard 30-day API retention (state that honestly), or the design must not depend on ZDR.
- 'PACKS ARE DATA-ONLY, SO THE BLAST RADIUS OF A COMPROMISED PACK IS BOUNDED AT WRONG TEXT' IS FALSE. For a directive, position-aware trading assistant, 'wrong text' IS the loss event — that is the entire product. Worse, claims are retrieved into Claude prompts, so a poisoned claim is a persistent, signed, schema-valid prompt injection that arrives through the trusted channel rather than the untrusted-content firewall. And the claim types 'interpretation', 'rule_of_thumb' and 'analogue' are non-numeric by definition, so they bypass the citation-span-validity check entirely. The stated bound is the most dangerous sentence in the security section.
- 'THE AGENT COMMITS; ONLY CI SIGNS — THE KEY IS NEVER REACHABLE FROM THE AGENT' IS FALSE AS DESIGNED. The pack pipeline triggers on tag `kb-*` and the workflow executes from the tagged ref. An agent (or anyone who compromises the agent's token) with write access to that repo can modify `.github/workflows/*.yml` and tag it; the modified workflow runs with the Ed25519 signing secret. This is exactly the tj-actions/changed-files class of failure. The same defect applies to the Azure Artifact Signing service principal on the `v*` tag workflow, so BOTH trust roots — code signing and pack signing — collapse to one repo secret an autonomous agent can reach.
- 'web_fetch IS STRUCTURALLY UNABLE TO CONSTRUCT URLs' IS OVERSTATED. The model supplies the URL; the only control is the `allowed_domains` allowlist. Since sec.gov and efts.sec.gov must be allowlisted for the pipeline to work, an injected instruction can still encode data into a request path or query against an allowlisted host. State the control accurately as 'domain allowlist plus no attacker-controlled host', and note that domain allowlisting is not a confidentiality control for hosts that log requests.
- NCRYPT_REQUIRE_VBS_FLAG DOES NOT DO WHAT THE PLAN CLAIMS AGAINST ADVERSARY #1. VBS key isolation prevents the private key material being dumped from process memory or exported in plaintext, including by an admin-level attacker. It does NOT bind the key to a code identity. A CNG persisted key is protected by the key-container ACL, which by default is the creating USER. Malware running as the user calls NCryptOpenKey + NCryptDecrypt and gets plaintext out of the oracle. The uplift over DPAPI is real but narrow: it defeats offline/passive file theft and forces on-box residency. The plan's framing ('converts an exportable secret into a non-exportable handle, forcing malware to stay resident — detectable and rate-limitable') is only true if something actually detects and rate-limits, and nothing in the plan does.
- 'SEC EDGAR — PUBLIC DOMAIN' (Provider Capability Matrix, `SecEdgarAdapter`, PermitsDerivedWorksOffMachine = Yes) IS WRONG AS STATED. EDGAR filings are the filers' copyrighted works hosted by a government agency; the SEC's access terms permit use, but there is no public-domain dedication of the documents. Facts extracted from them are unprotectable and the intended use is fine, but the pass-list rationale for the Derived-Works Firewall should say 'facts extracted from public filings, per SEC access terms' rather than 'public domain', because the latter would also license wholesale republication of filing text into knowledge packs.
- EU AI ACT ANALYSIS IS BACKWARDS. The plan files Art. 50 entirely under 'if a second user appears'. (a) The Art. 2(10) personal/non-professional deployer exemption is read restrictively: per the Commission's Art. 50 guidance, an activity through which a natural person gains economic benefit on a regular basis is a PROFESSIONAL activity. A sophisticated trader trading his own capital for profit will not sit inside that exemption. (b) Art. 3(11) 'putting into service' expressly includes supply for OWN USE, so building this for himself makes him the provider, and Art. 50(1)/(2) attach to providers. Net: if the user is EU-resident, Art. 50 may bite at one user; if UK-resident, the AI Act does not apply at all. The plan never establishes which — see the jurisdiction gap.
- 'CT PLAN APPROVED JULY 2026, DEFINES PROFESSIONAL BY USE INCLUDING LIMITED LIABILITY COMPANY' IS UNVERIFIED AND LOAD-BEARING. The professional per-device tape rates the plan quotes ($26 Tape A / $23 Tape B / $24 Tape C ≈ $73) are corroborated, and the CT Plan is on track for an early-2027 launch, but the July-2026 approval order and the quoted use-based professional definition could not be confirmed from a primary source. ## Review pass 4

**Verdict.** Unusually literate spec that fails on the execution details a real user hits in minute one. Three structural problems. (1) The WCAG 2.2 AA claim is false as specified: the DEFAULT density (22px rows) fails SC 2.5.8's own spacing math, and --text-tertiary at 10px carries the as-of provenance stamps at a measured 4.15:1, failing 1.4.3 — the trust layer is the least legible thing on screen. (2) The keyboard map contains three self-collisions inside its own tables (Ctrl+Shift+C, Ctrl+Shift+T) and binds its two most important keys — Ctrl+Space and the whole Ctrl+Alt+0..6 link-channel family — to combinations Microsoft explicitly tells developers to avoid (IME toggle; AltGr on international layouts). (3) The FACT/INFERENCE firewall, the plan's answer to the money-risk harm vector, is violated by its own flagship mockups: PAY, INS and the Conviction Score all put model output inside FACT-styled grids, and background polarity is a signal users habituate to within a week and that survives neither screenshot nor clipboard. Separately the mockups are arithmetically unbuildable (Mockup 2 sums to 1518px in a 1334px body; Mockup 5 contradicts itself on column widths in adjacent lines), and the discipline features are designed to be switched off — a non-dismissible post-trade review plus "a thesis without an invalidation condition is a hope" will cause the user to abandon the manual ledger, silently killing signature feature #10. The cheapest high-value fixes are the defaults: timezone/quiet-hours, contrast, target size, modifier families, and making INFERENCE visible at the glyph level rather than the background level.

### Corrections

- Contrast table is not measured. Recomputed against #12151A: --text-primary #E6EAF0 is 15.45:1 (plan says 13.6); --text-secondary #9AA4B2 is 7.39:1 (plan says 6.2); --text-tertiary #6C7887 is 4.15:1 (plan says 3.4); --down-default #F0813C is 7.03:1 (plan says 7.4). --up-default #4EA3F0 checks out at 6.95:1. At 10px (as-of stamps) and 12px it is normal text requiring 4.5:1; measured 4.15:1 fails. The product's single most important trust affordance is specified as a WCAG failure.

Verified: the exception requires 24px-diameter circles centred on each undersized target not to intersect, i.e. centres >=24px apart. Row pitch 22px (Compact, the DEFAULT) and 18px (Dense) both fail. - 'Channel hues are reserved and never reused for direction, selection or status' is false in the plan's own token table. C3 Teal is #56B6C2 and --fact-marker is #56B6C2 — identical hex. C2 Purple #C678DD is also used for the AVWAP-13D line, the TRF print tint and the 10b5-1 plan band. Verified: on Windows, AltGr on international layouts emits Ctrl+Alt, and Microsoft's own guidance ('Why Ctrl+Alt shouldn't be used as a shortcut modifier', The Old New Thing) says to avoid it. The plan binds Ctrl+Alt+0..6 (link channels, a core interaction) and Ctrl+Alt+Space (global raise). On a UK layout AltGr+4 is the euro sign.

- '44 commands' in the Section 5 heading; the table lists 59 mnemonics (DES through SET). 59 is roughly 3x what Bloomberg power users actually retain, so the count error is a learnability claim, not a typo.
- Alt+P freeze copy reads '247 updates buffered', implying replay on resume. The architecture specifies the quote lane as BoundedChannel(4096, DropOldest) with 'lane 3 stops draining' — those updates are discarded, not buffered. The copy promises data the system threw away.
- SC 2.4.11 (Focus Not Obscured, Minimum) concerns whether the focused component is hidden, not general content occlusion. It is cited as the reason floating toasts are banned. The decision is right, the citation is wrong, and a wrong SC in a build spec invites someone to 'fix' it back.
- The 13F honesty strip says 'filed up to 45 days after quarter end ... 68 days old' while elsewhere the plan says '13F (up to ~135 days)'. Both are true of different things (deadline vs oldest position in the report). The strip is called the product's central honesty claim and currently understates staleness by ~90 days for early-quarter positions.
- Module 12.6 specifies P1 alerts as 'modal toast + sound + Windows notification'. Module 16.13 and Mockup 1 specify toasts render in the status rail, never floating, max 1 at a time. Mutually exclusive. A modal also steals focus, eating in-flight command-line keystrokes during exactly the events P1 is reserved for.
