every choice with the alternative I rejected

Twenty years of this has taught me one thing about stack decisions: the cost isn't the choice, it's the reversal. So below is what I'd pick, and — more usefully — what I'd have picked instead and why I didn't. A plan that only lists winners is hiding its reasoning.

Layers, and the one contract people get wrong

LayerContainsContracts

ProvidersOne adapter per vendor, each declaring its capabilities and entitlementsICapabilityDeclaring
Local storeDuckDB/Parquet lake, SQLite app store, encrypted user store, pack storeIRepository<T>
BackgroundIngest workers, release-calendar scheduler, pack sync, embedding rebuildIScheduledJob
AI boundaryAnalysis service — no credentials, no filesystem write, no bridge handleIAnalysisRequest → text

One interface per capability, never per vendor — vendors get replaced, capabilities don't. A router picks the cheapest capable source per request. Schema drift is caught by contract tests against recorded fixtures plus a nightly live canary. A dead provider degrades to last-known-good with a visible age stamp rather than taking the panel down.

IBulkDatasetSource is separate on purpose, and this is the contract people get wrong. A good deal of regulatory data ships as ZIP archives, not as an API. A provider layer that models only per-request endpoints will quietly lead you into designing a multi-week polite crawl for data that downloads in four minutes. I've seen that mistake cost a quarter. Modelling bulk as a first-class shape at the interface level is what prevents it.

The Form 4 path, with a latency budget

This is the hop-by-hop budget for the one path that has to be fast, because it's the product's reason to exist. Target: on screen within 60 seconds of the filing hitting EDGAR. Budgets are stated per hop so that when it regresses you know which hop to look at rather than profiling the whole thing.

#HopMechanismBudgetFailure handled
1DetectPoll the EDGAR current-filings Atom feed at 2s, inside the 10 req/s fair-access ceiling, with a declared contact User-Agent.≤2sA generic browser UA earns an immediate SEC block page — this is a documented policy, not a rate limit you can retry through.
2FetchPull the Form 345 XML by accession number.~300msJittered backoff; circuit-break on repeated 403 rather than hammering.
3ParseownershipDocument — derivative and non-derivative tables, transaction codes, footnotes, and the document-level aff10b5One flag.~50msSchema drift quarantines the document and raises an alert. Never a silent drop — a silently dropped filing is indistinguishable from no filing, which is the worst failure this system has.
4ResolveCIK → FIGI → instrument. Supersede any prior 4/A amendment.~20msTicker reuse and name changes never corrupt identity.
5ScoreConviction model plus routine/opportunistic classification and cluster recompute.~30msDeterministic by design — there is no model call in this path, so it cannot stall on a provider.
6Fan outTape row, cluster leaderboard, alert evaluation, chart ribbon marker.~50msBackpressure via bounded channels; a slow consumer drops frames, never blocks ingest.
7RenderConflated to frame rate. A raw event stream is never bound to the UI thread.≤16msFlash governor caps at 3/sec — a WCAG requirement that happens to also be what you want at 09:30.

That vector cap is a deliberate design decision, not a limitation. Embedding the full filing corpus is roughly 4.7M chunks; brute-force search over that is a multi-second scan, so you'd need an ANN index, which brings its own corruption failure mode and its own rebuild time. Watchlist-only keeps retrieval under 100ms with no index that can go bad. Scope the corpus, not the algorithm.

Build, release and the boring operational discipline

ConcernApproach
CIGitHub Actions Windows runners: build, test, SBOM (CycloneDX), vulnerability scan, sign, publish.
Signing in CISigning secrets reachable only from a protected branch. Workflow files must themselves be protected and tag triggers restricted. A tag-triggered workflow runs from the tagged ref — so anyone who can commit a workflow file and push a tag can reach the signing key. That's the tj-actions class of compromise, and it applies to both the app pipeline and the knowledge-pack pipeline. This is the control I'd check first on any repo I inherited.
Release channelsalpha / beta / stable, delta updates, previous version retained on disk so rollback is a local operation and not a download.
Crash reportingLocal-only by default with explicit opt-in to send. Structured logging with a field allow-list, not a deny-list — keys, tokens, prompt text and quote data are never loggable. Deny-lists fail open; allow-lists fail closed.
Provider breakageContract tests against recorded fixtures, a nightly live canary per provider, schema-drift quarantine. Expect breakage several times a year. The abstraction exists to make each one a one-file fix rather than a weekend.
Effort ledgerEstimated versus actual per feature, committed to the repo from the first week. After ten features you know your real multiplier, and every estimate in COST stops being a guess and becomes a calculation. This is the cheapest thing in the plan and the one most likely to be skipped.
